Admin Setup Guide

This site is hosted as static files. Supabase Auth protects the dashboard interface; database and media writes are enforced by Supabase RLS and the Edge Function.

Credentials are never created on this page. Create or invite the administrator in the Supabase Dashboard, choose a new password there, and do not place it in this repository.
  1. Run every SQL migration in supabase/migrations/ in timestamp order, through 20261031120000_security_hardening.sql.
  2. In Authentication, create or invite hodvlsi@siet.ac.in, confirm the email, and disable public sign-ups.
  3. In the SQL Editor, assign the trusted server-side admin claim after the account exists:
    UPDATE auth.users SET raw_app_meta_data = COALESCE(raw_app_meta_data, '{}'::jsonb) || '{"site_admin":true}'::jsonb WHERE lower(email) = 'hodvlsi@siet.ac.in';
  4. Set a strong password and recovery redirect URL in Supabase Auth settings. Consider enabling MFA and CAPTCHA or rate protection.
  5. Deploy supabase/functions/gallery-media with the Supabase CLI. Ensure its secret key exists only in Supabase Edge Function secrets.
  6. Review Storage policies for broad pre-existing rules. The gallery bucket must remain private; public media is served through short-lived URLs for published records.

After setup, test that an anonymous visitor can read published events and gallery media, cannot read drafts or submit management operations, and that only the authorized admin can write.
